# frontend-design 적용 규칙 (이 저장소용 보충, 2026-10-28)

`SKILL.md`(Anthropic 원문)는 웹 UI 기준으로 쓰였다. 이 저장소에서는 **인스타그램 카드뉴스, 블로그 썸네일·인포그래픽, 구글 폼 이미지**처럼 HTML로 그려 PNG로 내보내는 이미지에 적용한다. 원문의 원칙과 아래 규칙이 부딪히면 **아래 규칙(브랜드 규칙)이 우선**한다. 원문도 "브리프가 정한 것은 그대로 따르라"고 한다.

## 바꾸지 않는 것 (브리프로 고정)
- 색: 메인 `#1E2A78`(네이비), 포인트 `#FF5A36`(오렌지), 보조 배경 `#F4F6FB` — `brand/profile.md`
- 폰트: Pretendard (`.claude/skills/aeo-blog/assets/fonts/`). 다른 서체를 섞지 않는다
- 로고: 사업부 공유폴더 원본(`무단 수정 금지`). 색·비율·요소를 바꾸지 않는다. 흰색 버전은 어두운 배경, 컬러 버전은 밝은 배경에만
- NAP(기관명·주소·전화·운영시간)는 `brand/profile.md` 표기를 글자 그대로
- 문체: 해요체. 지어낸 학원 정보(합격률·수강료·강사진) 금지
- 규격: 카드뉴스 1080×1350(4:5), 프로필 격자에서 좌우 약 34px가 잘리므로 글자는 안쪽 80px 안에 둔다. 휴대폰에서 가로 약 360px로 줄어드니 본문 글자는 30px 이상

## 원문에서 특히 지킬 것 (지금 결과물에서 자주 나온 기본값)
1. **제목에서 단어 하나만 색 바꾸는 강조**를 기본으로 쓰지 않는다. 강조가 필요하면 글자 크기·굵기·줄 나눔으로 하거나, 한 장에 한 번만 색을 쓴다
2. **내용을 똑같은 둥근 카드로 잘라 넣고 같은 그림자**를 반복하지 않는다. 카드(상자)는 비교·선택지처럼 '묶음'이라는 정보가 있을 때만. 나열은 여백과 줄 간격으로 구분한다
3. **번호 표시(1·2·3)는 실제 순서(절차·시간순)일 때만**
4. 링크·버튼 끝 `→`, 가운뎃점으로 이어 붙인 `A · B · C` 부제, ALL CAPS 눈썹 라벨을 습관적으로 쓰지 않는다
5. **과감함은 한 곳에**: 장마다 기억에 남는 요소 하나(큰 숫자, 큰 제목, 한 장면 그림)를 정하고 나머지는 조용하게
6. 글은 장식이 아니라 내용이다. 각 장은 한 가지만 말하고, 독자(고등학생·학부모·구직자)가 쓰는 말로 쓴다

## 작업 순서 (원문의 '계획 → 검토 → 제작 → 자기 비평')
1. 브리프 정리: 주제·대상·이 이미지의 역할(표지인지, 설명 장인지, 상담 유도 장인지)
2. 계획: 색 배치(네이비·오렌지·밝은 배경 중 어느 쪽을 바탕으로), 글자 크기 단계, 배치 스케치(ASCII), 이 시리즈만의 특징 한 줄
3. 검토: "같은 주제를 다른 학원이 맡겨도 똑같이 나올 디자인인가?" 그렇다면 그 부분을 바꾼다
4. 제작: `.canvas` 요소에 그리고 `node .claude/skills/aeo-blog/scripts/render.mjs <폴더>`로 PNG 렌더링
5. 자기 비평: 렌더링한 PNG를 열어 본다. 휴대폰 크기(가로 360px)로 줄여 글자가 읽히는지, 격자(3:4 자르기)에서 글자가 잘리지 않는지 확인. 장식 하나를 빼 본다
