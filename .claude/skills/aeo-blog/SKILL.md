# AEO 블로그 자동 작성 (네이버 + 티스토리 + 이미지)

근거 문서: `docs/01_AEO_리서치_요약.md`, `docs/02_자동화_파이프라인_개요.md`
브랜드 정보: `brand/profile.md` — NAP(이름·주소·전화·운영시간)는 이 파일 표기를 **그대로** 복사한다. 빈칸은 추측하지 않고 `[확인 필요]`로 남긴다.

## 입력

- 필수: 키워드 (예: `게임학과 내신 5등급`) — 또는 `다음`/`추천`이면 아래 "키워드 선정"부터 수행
- 키워드 엑셀(네이버 검색광고 키워드도구 '전체 다운로드')을 올리면 `keywords/raw/YYYY-MM-DD_seed<번호>_<기준키워드>.xlsx`로 저장 후 키워드 선정 수행
- 선택: 메모, 실제 상담 사례, 참고 URL, 플랫폼 지정(기본: profile의 `both`)

## 키워드 선정 (키워드 미지정 시)
1. `pip install openpyxl` (없으면) → `python3 .claude/skills/aeo-blog/scripts/keywords.py`
   - `keywords/raw/*.xlsx` 병합 → 관련 키워드만 질문군별 정리(`backlog.md/csv`) → 주제 묶음별 합산 검색량(`clusters.md`)
   - 관련성 규칙(질문군 패턴·제외어)은 스크립트 상단 `GROUPS`/`EXCLUDE`, 주제 묶음은 `keywords/clusters.csv`에서 관리. 새 엑셀에서 묶음에 없는 유망 키워드가 보이면 clusters.csv에 행을 추가한다
2. 추천 기준: ① 상태가 빈 묶음 중 ② 학원 상담 의도가 강한 것(입시·직군·취업 > 도구 이름·회사명 검색) ③ 합산 검색량 순. 허브(입시 허브·취업 허브)를 먼저 쓰고 직군·입시 세부 주제를 이어서 쓴다
3. 사용자에게 추천 2개와 근거(합산 검색량·포함 키워드)를 보여 주고 확인받은 뒤 작성한다
4. 글 작성 후 `keywords/used.csv`에 `대표키워드,작성일,글폴더` 추가, `keywords/clusters.csv` 해당 행 `상태`에 `작성 YYYY-MM-DD` 기입 → 스크립트 재실행

## 절차

### 0. 준비
1. `brand/profile.md`, `templates/` 전체, `docs/01_AEO_리서치_요약.md`를 읽는다.
2. 작업 폴더 `posts/YYYY-MM-DD_슬러그/`와 `images/src/`를 만든다. (슬러그: 키워드를 하이픈으로 연결)

### 1. 질문 변환 (키워드 → 질문군)
- 키워드를 잠재고객이 실제로 검색하거나 AI에게 물을 법한 **상황형 질문**으로 바꾼다.
- 산출: 핵심 질문 1개, 하위 질문 4~5개(검색 의도 단위, 겹치지 않게), 후속 질문 2~3개(다음 글 후보).
- **키워드의 모호성을 먼저 점검한다.** 같은 말이 대상에 따라 다른 뜻이면(예: 내신 9등급제 vs 5등급제의 "5등급") 그것을 첫 하위 질문으로 삼는다.
- 발행 시점의 입시 일정(수시 접수 완료 여부 등)을 고려해 **지금 읽는 사람이 할 수 있는 행동**을 기준으로 답한다.

### 2. 리서치
- 웹 검색으로 각 하위 질문의 공식 근거(대학 모집요강·시행계획, 교육부·대교협 발표, 공신력 있는 언론)를 찾는다.
- 모든 근거는 `report.md`에 `출처명 / URL / 기준 학년도·시점 / 확인 방법(원문 열람 or 검색 요약)`으로 기록한다.
- 원문을 직접 열지 못하고 검색 요약으로만 확인한 수치는 report에 "원문 대조 필요"로 표시한다.
- 연도가 지난 수치는 쓰더라도 본문에 기준 학년도를 반드시 붙인다. **수치를 지어내지 않는다.**

### 3. 개요
- `templates/post-template.md` 구조로 질문·근거를 배치한다.
- 질문 성격별 블록: 정의형 → 정의 문단, 방법형 → 번호 목록, 비교형 → 표.

### 4. 본문 작성 — 플랫폼별 2편

공통 규칙
- 서두 3~5줄 안에 결론. 첫 문장이 곧 답.
- 모든 H2는 질문형, **답변 블록 4단계**: ① 질문 소제목 → ② 첫 1~3문장(80~150자) 직답 → ③ 근거 + 기준 시점 → ④ 행동 방법 + 다음 질문 연결.
- 한 문단 = 한 내용. 추상적 홍보 문구 대신 구체적 과정·순서.
- 브랜드 맥락은 2~3곳에만 자연스럽게. 키워드 반복 금지.
- 문체: 해요체.

**가상 사례 규칙** (profile: 가상 사례 사용)
- 사용자 제공 실제 사례가 있으면 그것을 우선 사용한다.
- 없으면 질문에 가장 전형적인 상황의 가상 사례 1개를 만든다. 고지는 **안내문처럼 보이지 않게 본문 일부로** 넣는다 (2026-10-01 발행분에서 `※` 고지 줄이 안내문으로 오인되어 두 플랫폼 모두 삭제됨):
  - 소제목에 `(가상 사례)`를 포함한다. 예: "상담에서 자주 만나는 상황 (가상 사례)"
  - 사례 첫 문장을 고지 문장으로 시작한다. 예: "아래는 상담에서 자주 나오는 고민을 재구성한 가상 사례예요."
  - `※`, `[ ]` 기호는 고지에 쓰지 않는다 — 이 기호들은 '붙여넣은 뒤 지우는 안내 표시'로만 사용한다.
- 가상 사례에는 실명, 실제 합격 대학명, 합격·취업 결과를 넣지 않는다. 사례는 "상황 → 고민 → 확인한 것 → 세운 계획"까지만 쓴다.
- 가상 사례는 FAQ 스키마에 넣지 않는다.

**FAQ 정책** (2026-10-03 변경 — 구글: 실제 FAQ가 아닌 곳에 FAQ 마크업 금지)
- 기본은 **FAQ 없음**. 본문 소제목에서 답하지 않았지만 검색 의도상 꼭 남겨야 할 **실제 질문**이 있을 때만 2~3개 작성한다
- 본문 내용을 반복하는 FAQ, 개수를 채우기 위한 FAQ는 만들지 않는다
- FAQ가 없으면 FAQ 섹션과 FAQPage 코드를 모두 생략한다(네이버·티스토리 동일하게)
- FAQPage 외 BlogPosting 코드는 넣지 않는다 — 티스토리 스킨이 이미 BlogPosting을 출력함(2026-10-01 발행분에서 확인)

**플랫폼별 차별화** (유사문서 판정 방지)
- 같은 사실·근거를 쓰되 **제목, 서두, 소제목 문장, 문단 순서, 예시 표현**을 다르게 쓴다. 문장을 그대로 복사하지 않는다.
- `naver.md` (네이버 스마트에디터용)
  - 제목: 대화형 질문 + 지역 키워드(예: "~일까요? 대전 게임학원이 정리했어요")
  - 짧은 문단(2~3문장). 표는 쓰지 않고 목록 또는 인포그래픽 이미지로 대체
  - 소제목 줄은 `[소제목] ` 접두어로 표시 → 사용자가 '소제목' 서식 적용 후 접두어 삭제 (■ 기호는 쓰지 않음: 서식 없이 남으면 본문과 구분이 안 됨)
  - 요약은 `[인용구] ` 접두어 줄로 표시 → 인용구 '라인'형·왼쪽 정렬 적용 안내
  - 이미지 위치를 `[이미지: 파일명 / 사진 설명: …]`로 표시. 사진 설명은 사진 아래 보이는 캡션이므로 독자가 읽는 자연스러운 한 문장으로 쓴다(키워드 나열 금지)
  - **글 끝 순서 고정**: (FAQ가 있으면) FAQ → 다음 글 예고 → 참고 자료 → 연락처(NAP) → `[지도]` 표시. (참고 자료를 지도 뒤에 두면 지도 삽입 후 누락되기 쉬움)
  - `naver.md`에는 제목·태그·작성 안내를 넣지 않는다. 본문만 담고, 나머지는 `naver-붙여넣기안내.txt`로 분리한다
- `naver-붙여넣기안내.txt`: ① 제목 한 줄 ② 본문 붙여넣기 ③ 서식 적용(소제목 서식·본문 글자 크기 15·인용구 라인형 왼쪽 정렬) ④ 이미지와 사진 설명 목록(파일명 → 캡션 문구 표) ⑤ 지도 삽입 ⑥ 태그 한 줄 ⑦ **발행 전 '지우면 안 되는 것' 확인**(가상 사례 소제목·첫 문장, 참고 자료, 연락처) ⑧ `[ ]` 표시가 남지 않았는지 확인
- 티스토리는 **두 파일**로 나눈다 (초보자도 '전체 복사'만 하면 되도록)
  - `tistory.html`: 본문 HTML만. 안내 주석·제목·`<script>`를 넣지 않는다 → 파일 전체를 그대로 붙여넣는 용도
    - 제목 성격: 정보형 질문 + 범위(예: "~ 가능할까? 9등급제·5등급제별 정리 (2027~2028 대입)")
    - `<h2>/<h3>`, `<ul>`/`<ol>` 사용
    - **표·요약 박스·가상 사례 박스·회색 보조 문구는 `templates/tistory-components.html`의 인라인 스타일 부품을 그대로 사용**한다
      - `<blockquote>` 금지 (스킨이 가운데 정렬함) → 요약 박스 부품 사용
      - 모든 `<table>`은 가로 스크롤 래퍼(`overflow-x:auto`) 안에 넣고 `word-break:keep-all`, 첫 열 `white-space:nowrap` (모바일에서 "매/우/큼"처럼 세로로 쪼개지는 문제 방지)
      - 표는 열 3개 이하를 원칙으로 한다. 4열이 꼭 필요하면 `min-width:640px`
    - 이미지 자리: `<p>[이미지 업로드: 파일명 / 대체텍스트: …]</p>`. 대체텍스트(alt)는 화면에 안 보이고 검색엔진·AI가 읽으므로 이미지 속 핵심 수치·결론을 문장으로 담는다
  - `tistory-붙여넣기안내.txt`: ⓪ 카테고리 지정 안내(미지정 시 '카테고리 없음'으로 발행됨) ① 제목 ② 본문 붙여넣기 방법 ③ 이미지 방법 ④ FAQPage JSON-LD `<script>` 전체(본문 FAQ와 토씨까지 동일, "맨 마지막에 붙이고 모드 전환 금지" 안내) ⑤ 태그 한 줄 ⑥ 발행 전 '지우면 안 되는 것' 확인(가상 사례 고지, 참고 자료) ⑦ 발행 후 확인법 — 이 순서로 작성 (`posts/2026-10-01_게임학과-내신-5등급/tistory-붙여넣기안내.txt` 형식 참고)

### 5. 이미지 생성
- `images/src/`에 1080×1080 HTML을 만든다. 공통 스타일은 `<link rel="stylesheet" href="<상대경로>/.claude/skills/aeo-blog/assets/card.css">`.
- 기본 세트:
  - `thumb-naver.html`, `thumb-tistory.html`: 플랫폼별 썸네일(제목 문구 다르게)
  - 인포그래픽 2~3장: 본문의 핵심 표·비교·단계(로드맵)를 시각화. 수치는 본문과 동일하게, 하단에 출처·기준 학년도 표기.
  - 가상 사례·인물 사진·로고는 만들지 않는다(학원 로고는 사용자가 직접 삽입).
- **실제 사진 자리 2곳** (사용자가 직접 촬영해 삽입) — 원고에 `[실제 사진 1: 촬영 가이드 …]` 형식으로 표시
  - 네이버: 실제 사진 2장 / 티스토리: 실제 사진 1장(네이버와 다른 컷 권장)
  - 사진 1 = **주제 관련 실물** (예: 모집요강 정리지, 포트폴리오·실기 연습물, 수업 화면). 해당 내용을 설명하는 소제목의 직답 문단 바로 아래
  - 사진 2 = **학원 공간** (상담실·강의실·입구 간판). 연락처 블록 바로 위 (네이버: 연락처 → 지도 앞)
  - **가상 사례 섹션 안·바로 옆에는 실제 사진을 두지 않는다** (가상 사례가 실제 사례처럼 보이게 됨)
  - 안내 파일에 사진별 촬영 가이드(구도·피해야 할 것)와 사진 설명 문구를 함께 적는다
  - 촬영 공통 기준: 가로 4:3, 가로 1,500px 이상, 자연광·밝게, 얼굴·이름·모니터 속 개인정보가 보이지 않게(학생 얼굴은 동의 없으면 금지), 글자 합성·스톡 사진·과한 필터 금지, 최근 촬영본
- 이미지 총량: 네이버 6장(생성 4 + 실제 2), 티스토리 5장(생성 4 + 실제 1). 근거는 docs/01 "이미지 기준" 참고 — 개수 자체는 공식 기준이 아니라 운영 권장값
- 렌더링: `node .claude/skills/aeo-blog/scripts/render.mjs posts/<폴더>/images`
- 렌더 후 PNG를 직접 열어 글자 잘림·겹침이 없는지 확인하고, 문제가 있으면 HTML을 고쳐 다시 렌더링한다.

### 6. 자체 검수
- 작업 폴더에 `meta.json`(제목·태그·카테고리)을 만들고 `python3 .claude/skills/aeo-blog/scripts/build_guides.py posts/<폴더>` 실행
  → 두 붙여넣기 안내 파일 자동 생성(FAQ 코드는 본문 FAQ에서 자동 추출 → 문장 일치 보장) + 자동 점검(※ 사용, 가상 사례 고지, 글 끝 순서, NAP, 표 래퍼·열 수, blockquote, 지도 표시). "이상 없음"이 나올 때까지 수정
- `templates/checklist.md` 항목을 **두 원고 각각** 점검해 `report.md`에 ✅/❌로 기록한다.
- ❌는 고친 뒤 재점검. 사실 확인처럼 자동으로 해결할 수 없는 것은 "발행 전 확인" 목록으로 넘긴다.

### 7. 저장 및 전달 (매번 수행)
1. **Git 보관**: 작업 폴더를 커밋하고 현재 작업 브랜치에 push한다. (클라우드 세션은 종료 시 파일이 사라지므로 생략하지 않는다.)
2. **다운로드용 압축**: 이미지 원본(`images/src`)을 제외하고 작업 폴더를 zip으로 묶는다. `meta.json`·`tistory-faq.html`은 업로더가 쓰므로 **포함**한다.
   - 파일명: `키워드-슬러그_YYYY-MM-DD.zip`, 위치: 세션 스크래치패드(없으면 `posts/`가 아닌 임시 폴더 — 저장소에 zip을 커밋하지 않는다)
   - 예: `cd posts && zip -qr "<스크래치패드>/<슬러그>_<날짜>.zip" "<폴더>" -x "*/images/src/*"`
3. **전달**: SendUserFile로 zip 1개를 `display: attach`로 보낸다. 미리보기용으로 썸네일 PNG 2장도 함께 보낸다.
4. 원고를 수정한 경우에도 1~3을 다시 수행해 최신 zip을 전달한다.

### 7-1. 티스토리 업로더 (사용자 PC)
- `tools/tistory-uploader/`: 사용자 Windows PC에서 실행. 원고 zip을 `posts/`에 풀고 `upload.cmd` → 이미지 업로드·본문·FAQ 코드·카테고리·태그 입력 → **비공개 저장**(확인 못 하면 중단)
- 실제 사진은 글 폴더의 `photos/실제사진N.jpg`로 넣으면 자동 첨부, 없으면 안내 줄 유지
- 업로더 실패 메시지를 사용자가 전달하면 원인(티스토리 화면 변경 등)을 고쳐 `tools/tistory-uploader` 새 zip을 전달

### 8. 발행 후 점검 (사용자가 발행 URL을 주면)
1. `node .claude/skills/aeo-blog/scripts/review.mjs <티스토리URL> <네이버URL> <스크래치패드>/review` 실행 (한쪽만이면 다른 쪽에 `-`)
2. `review.json`의 `searchReadiness`(비로그인 공개 접근·robots·RSS·사이트맵 포함)를 확인한다. 통과해도 실제 색인은 네이버 서치어드바이저·구글 서치콘솔 URL 검사로만 확인 가능함을 안내
3. `review.json` 자동 점검 결과 + PC·모바일 캡처(`t-desk-*`, `t-mob-*`, `n-desk-*`, `n-mob-*`)를 직접 열어 확인한다.
   - 네이버 이미지가 흐리게 찍히는 것은 지연 로딩 때문이므로 문제로 보지 않는다. 깨짐 여부는 `imagesBroken`으로 판단한다.
4. 결과를 "반드시 고칠 것(누락·규정) / 가독성 개선 / 참고" 3단계로 보고하고, 반복되는 문제는 이 SKILL.md와 템플릿에 반영한다.
5. 접속이 막히면(egress 차단) 사용자에게 환경 설정에서 네트워크 접근 허용을 안내하거나 캡처를 요청한다.

마지막 보고(사용자에게): 두 원고 제목, 핵심 답 1문장, 이미지 목록, 체크리스트 결과, 발행 전 확인 항목, zip 파일명.
