## 1. AEO 정의

**AEO(Answer Engine Optimization)** = 사용자가 실제로 묻는 *질문* 단위로 콘텐츠를 설계해,
검색엔진·AI 답변 엔진(구글 AI 개요/AI 모드, ChatGPT, Perplexity, Gemini, Claude 등)이
**답변의 재료로 바로 추출·인용할 수 있게** 만드는 작업입니다.

| 구분 | 핵심 질문 | 초점 |
|---|---|---|
| SEO | 우리 콘텐츠가 발견되는가? | 검색어 일치, 페이지 구조, 노출·클릭 |
| GEO | AI가 이해하고 신뢰할 수 있는가? | 검증 가능한 출처, 구체적 수치·사례, 요약 가능한 구조 |
| AEO | 이 정보가 질문의 답으로 바로 쓰일 수 있는가? | 한 질문에 한 답, 결론 우선 + 근거 후속, 채널 간 맥락 축적 |

세 가지는 대체 관계가 아니라 **누적 관계**입니다. (SEO → GEO → AEO)

## 2. 왜 필요한가 (PDF 4가지 이유)

1. 검색어가 '단어'에서 '상황형 질문'으로 길어짐 (예: "내신 낮은데 게임학과 갈 수 있을까?")
2. 클릭 전에 답이 소비됨 (제로클릭). 외부 조사에서도 검색의 약 60%가 클릭 없이 종료된다는 수치가 인용됩니다. *(업계 집계치이므로 참고용)*
3. 브랜드 평가는 단일 문서가 아니라 반복되는 맥락에서 형성됨
4. 기존 콘텐츠를 버리지 않고 확장 가능

## 3. AEO 5대 원칙 + E-E-A-T

| # | 원칙 | 블로그 적용 |
|---|---|---|
| 01 | 질문 명확성 | 글 하나 = 핵심 질문 하나 |
| 02 | 직접 답변 | 서두 3~5줄 / 소제목 아래 첫 1~3문장에 결론 |
| 03 | 근거·경험 | 공식 자료·수치·실제 상담 사례 + **기준 시점** |
| 04 | 브랜드 맥락 | 지역·과목·대상·브랜드 정보를 자연스럽게 연결 |
| 05 | 질문군 연결 | 마지막에 다음 질문(후속 글)으로 연결 |
| (6) | E-E-A-T | 누가 말하는가(강사 경력·자격, 실명 후기, 공식 자료) |

## 4. 블로그 7대 작성 기준 (PDF)

1. 질문형 제목
2. 서두 3~5줄 안에 즉답
3. 질문형 소제목 + 한 문단 = 하나의 내용
4. 주장에는 확인 가능한 근거·기준 시점
5. 추상적 홍보 문구 대신 구체적 과정·순서
6. 실제 상담에서 반복되는 질문·사례 활용
7. 마지막에 관련 질문 연결 (질문군 확장)

### AEO 답변 블록 4단계 (모든 소제목에 반복 적용)

```
1단계 질문 그대로 소제목      Q. 게임학과는 내신 성적을 얼마나 보나요?
2단계 첫 1~3문장 직접 답변    "내신이 낮다고 진학이 불가능한 것은 아닙니다. …"
3단계 근거 + 기준 시점        "A대학 ○○전형은 실기 ○%… (2026학년도 모집요강 기준)"
4단계 행동 방법 + 다음 질문   "목표 대학을 먼저 정하고… → 포트폴리오는 어느 수준까지?"
```

## 5. 외부 조사로 보강된 실무 기준

| 항목 | 내용 | 신뢰도 |
|---|---|---|
| 답변 길이 | 각 섹션 첫 답변은 **40~60단어(한국어 기준 약 2~3문장, 80~150자)** 로 완결 | 업계 다수 가이드 공통 권고 |
| 의미 단위 분할 | 한 섹션 = 한 개념. 정의·방법·비교를 한 섹션에 섞지 않음 | 업계 공통 권고 |
| 재사용 블록 | 정의 블록 / 단계 블록 / 장단점 블록 / 비교표 | 업계 공통 권고 |
| 수치·인용 | GEO 논문(Princeton 등, KDD 2024): 인용문 추가 시 가시성 +41%, 통계 추가 시 +31% (실험 환경 기준) | 학술 연구 — 단, 실험 벤치마크 결과이므로 실제 효과는 다를 수 있음 |
| 제목 위계 | H1 1개, H2(주요 섹션) → H3(하위), 단계 건너뛰지 않음 | 구글 공식 기본 원칙 |
| 구조화 데이터 | FAQPage → Article → Organization/LocalBusiness 순 우선. **화면 본문과 스키마 내용 100% 일치** | 구글: "AI 전용 마크업은 없다. 일반 품질 기준과 동일" |

### ⚠️ PDF 내용 중 보정이 필요한 부분

1. **FAQPage 스키마 효과의 한계**
   - 구글은 2023년 8월부터 FAQ 리치결과(검색결과에 질문 펼침 표시)를 정부·보건 등 권위 사이트로 제한했습니다. 일반 블로그에 FAQPage를 넣어도 *리치결과는 거의 표시되지 않습니다.*
   - 다만 기계가 Q&A 구조를 읽는 데는 도움이 되므로 **"넣어서 손해는 없는 보조 신호"** 정도로 보는 것이 정확합니다. "FAQ 스키마를 넣으면 AI 인용률 2~3배" 같은 수치는 마케팅 업체 자체 테스트로, 검증된 수치가 아닙니다.
   - 따라서 PDF의 "구글 Rich Results Test로 오류 확인"은 FAQ 적격성이 표시되지 않을 수 있으므로, **문법 검증은 [Schema Markup Validator](https://validator.schema.org/)** 를 함께 쓰는 것을 권장합니다.
2. **네이버 큐(Cue:) 종료(2026년 4월)** — PDF 기재 사항이며, 본 조사에서 별도로 교차 확인하지는 못했습니다. 게시 전 한 번 확인을 권장합니다.
3. **네이버 블로그는 스키마 삽입 불가** — 자동화 파이프라인에서 스키마 단계는 *티스토리/홈페이지용*으로만 산출합니다.

## 5-1. 이미지 기준 (2026-10-03 조사)

| 구분 | 내용 | 신뢰도 |
|---|---|---|
| 구글 공식 | 이미지는 관련 텍스트 가까이 배치, 원본성·실질적 정보가 있는 이미지만 사용, 중요한 이미지는 페이지 상단 근처, 대체텍스트 작성 ([Google Images SEO Best Practices](https://developers.google.com/search/docs/appearance/google-images)) | 공식 문서 |
| 네이버 | 이미지 **개수**에 대한 공식 기준은 확인하지 못함. D.I.A가 문서의 독창성·경험 정보를 평가한다는 설명은 있음 | 공식 기준 없음 |
| 업계 블로그 | "직접 찍은 사진 3장 이상", "원본 이미지 5장 이상" 등 ([로카포스팅](https://locaposting.com/blog/naver-seo-checklist), [브런치](https://brunch.co.kr/@imd08071/277)) | 검증되지 않은 경험칙 |

→ 운영 권장값: 네이버 6장(생성 4 + 실제 사진 2), 티스토리 5장(생성 4 + 실제 사진 1). 개수보다 **직접 촬영한 원본 사진**과 **관련 문단 바로 옆 배치**가 핵심.

## 6. AEO로 보기 어려운 콘텐츠 (금지 패턴)

- 질문형 제목만 있고 답이 늦게 나오는 글
- 키워드만 반복하는 글/후기
- 출처 없는 성과 단정 ("취업률 100%", "합격 보장")
- 한 게시물에 여러 질문을 섞은 글
- 채널마다 서로 다른 정보(학원명·주소·전화·커리큘럼 불일치)
- 실제 경험하지 않은 사례·후기 창작
