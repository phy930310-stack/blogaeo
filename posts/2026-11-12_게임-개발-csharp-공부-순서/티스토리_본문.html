게임 개발용 C#은 자료형·제어문, 클래스·구조체, 컬렉션, 상속·인터페이스, 델리게이트·코루틴 다섯 단계로 공부합니다. 단계가 끝날 때마다 콘솔 텍스트 RPG, 유니티 미니게임, 같은 게임 다시 짜기로 손에 익었는지 확인합니다. 유니티 스크립트 언어가 C#이고 확인한 유니티 공고가 직접 쓴 C# 코드를 요구하기 때문입니다.

Unity 6.6 매뉴얼 기준으로 유니티가 지원하는 문법은 C# 9.0까지입니다. 최신 C# 문법을 전부 따라갈 필요는 없습니다. 대신 유니티 안에서만 통하는 규칙 몇 가지를 따로 익혀야 합니다.

아래에서 쓰이는 곳, C++와의 선택 기준, 공부 순서, 유니티에서 달라지는 점, 확인 과제, 공고가 보는 수준을 차례로 답합니다. 유니티 설치와 에디터 사용법은 빼고 여기서는 언어만 다룹니다.

기준: Microsoft Learn C# 문서(둘러보기·대화형 자습서·버전 기록·C# 15 안내), Unity 6.6 매뉴얼(C# 컴파일러·MonoBehaviour·코루틴·관리 메모리), Unity Learn Junior Programmer 과정, 게임잡 채용 공고 3건(2026년 7~9월 등록). 2026년 11월 12일 작성

Q1. 게임 개발에서 C#은 어디에 쓰입니까?

유니티로 만드는 게임의 스크립트가 C#입니다. Unity 6.6 매뉴얼 설명으로는 MonoBehaviour 클래스가 스크립트를 게임 오브젝트에 붙이는 틀입니다. 새 스크립트를 만들면 Start와 Update 함수가 든 C# 클래스가 생깁니다.

언어 문서는 마이크로소프트가 Microsoft Learn에서 제공합니다. Microsoft Learn은 C#을 .NET 플랫폼에서 가장 인기 있는 언어이자 C 계열 언어로 소개합니다. C나 C++, 자바를 써 봤다면 중괄호와 세미콜론, if와 for 문법이 익숙하다고 설명합니다.

공고도 같습니다. 모바일 게임사 기어세컨드의 클라이언트 개발자 공고는 키워드에 C#과 Unity를 적었습니다(게임잡, 2026년 9월 29일 등록). 데브캣의 「마비노기 모바일」 게임 로직 프로그래머 공고도 C#과 유니티 프로젝트 경험을 지원 자격에 넣었습니다.

Q2. C#과 C++ 중 무엇부터 공부합니까?

가려는 회사가 쓰는 엔진이 정합니다. 유니티·모바일이 목표면 C#, 언리얼·PC·콘솔이 목표면 C++부터입니다. 아직 목표가 없으면 C#으로 작은 게임을 먼저 끝내는 쪽이 막히는 곳이 적습니다.

기준 C# C++
주로 쓰는 엔진 유니티 언리얼
메모리 관리 런타임이 자동으로 관리 개발자가 직접 관리
확인한 공고 기어세컨드 클라이언트 하이퍼센트 언리얼 신입

공고는 이 글과 「게임 개발 C++ 공부 순서」 글에서 확인한 게임잡 공고입니다.

C# 프로그램은 런타임의 자동 메모리 관리를 씁니다(Microsoft Learn). C++는 포인터와 메모리를 직접 다뤄야 해서 초반에 익힐 것이 더 많습니다. C++ 쪽 순서는 「게임 개발 C++ 공부 순서」 글에 따로 정리했습니다.

두 언어는 같은 C 계열이라 하나를 깊게 익히면 옮겨 가기가 수월합니다. 넥슨 넥토리얼 2026도 지원 자격에 'C++ 또는 C#'을 적었습니다. 엔진과 직무별 차이는 「게임 프로그래머 되는 법」 글에 있습니다.

Q3. C# 기초는 어떤 순서로 공부합니까?

다섯 단계입니다. Microsoft Learn 자습서와 Unity Learn Junior Programmer 과정의 순서를 게임 기준으로 묶었습니다. 각 단계가 게임에서 어디에 쓰이는지 한 줄씩 붙였습니다.

  1. 자료형·변수·제어문 — 체력과 점수를 담고 if와 반복문으로 규칙을 돌립니다. Microsoft Learn 자습서도 문자열과 숫자, 분기와 반복부터 시작합니다.
  2. 메서드·클래스·구조체 — 캐릭터와 아이템을 형식으로 만듭니다. 값 형식과 참조 형식의 차이를 여기서 잡습니다.
  3. 배열·List·Dictionary — 인벤토리와 적 목록을 담고 찾고 정렬합니다. Unity Learn 과정도 배열 다음에 리스트와 딕셔너리를 다룹니다.
  4. 상속·인터페이스·캡슐화 — 몬스터 공통 클래스를 만들고 종류별로 다르게 움직입니다. Unity Learn 과정의 마지막 미션이 이 객체 지향 원칙입니다.
  5. 델리게이트·이벤트·코루틴 — 체력이 바뀌면 UI가 알아서 갱신되고 연출을 여러 프레임에 나눠 실행합니다.

[이미지 업로드: 공통_csharp-roadmap.png / 대체텍스트: 게임 개발 C# 공부 순서 5단계 – 1단계 자료형·변수·제어문(체력과 점수, 규칙), 2단계 메서드·클래스·구조체(값 형식과 참조 형식), 3단계 배열·List·Dictionary(인벤토리와 적 목록), 4단계 상속·인터페이스·캡슐화(몬스터 공통 클래스), 5단계 델리게이트·이벤트·코루틴(UI 갱신과 여러 프레임에 걸친 연출)]

2단계에서 값 형식과 참조 형식을 꼭 구분해 둡니다. C#에서 int와 double, 구조체는 값 형식이고 문자열과 배열, 클래스는 참조 형식입니다(Microsoft Learn). 유니티의 Vector3도 구조체라 다른 변수에 담으면 값이 복사됩니다.

Microsoft Learn의 대화형 자습서는 프로그래밍 사전 지식이 없다고 가정하고 순서대로 진행합니다. Hello world, 숫자, 튜플과 형식, 분기와 반복, 리스트 컬렉션, 패턴 일치 여섯 단원입니다. GitHub Codespaces에서 실행할 수 있고 무료 GitHub 계정이 필요합니다.

Unity Learn은 Junior Programmer 과정을 12주 분량으로 안내합니다. 변수와 함수, 조건문과 배열, 반복문, 리스트와 딕셔너리, 객체 지향 원칙 순서로 게임을 만들면서 배웁니다. 유니티 기초를 먼저 익히고 시작하라고 권합니다.

Q4. 유니티에서는 C#을 어떻게 다르게 씁니까?

문법은 같지만 규칙이 네 가지 다릅니다. 시작점, 지원하는 문법 버전, 시간을 나눠 쓰는 방법, 메모리를 아끼는 습관입니다. 콘솔에서 배운 C#이 유니티에서 낯설게 느껴지는 것도 이 네 가지 때문입니다.

항목 일반 C# 유니티
시작점 Main 또는 최상위 문 Start와 Update
문법 버전 .NET 11 SDK 기본 C# 15 C# 9.0
시간 나누기 async와 await 코루틴(yield return)
메모리 습관 가비지 수집에 맡김 매 프레임 할당 줄이기

Microsoft Learn C# 문서와 Unity 6.6 매뉴얼 기준입니다. 2026년 11월 12일 확인.

[이미지 업로드: 공통_unity-csharp-rules.png / 대체텍스트: 일반 C#과 유니티 C#의 차이 – 일반 C#: Main 또는 최상위 문에서 시작, .NET 11 SDK 기본 버전은 C# 15, async와 await, 메모리는 런타임이 자동 관리 / 유니티 C#: Start와 Update에서 시작하고 생성자는 쓰지 않음, C# 9.0까지 지원, 코루틴(IEnumerator와 yield return)으로 프레임 나누기, 매 프레임 실행되는 코드에서 문자열 연결·박싱·클로저 줄이기]

유니티 스크립트에는 Main이 없습니다. Start는 첫 Update 직전에 한 번 불려 초기화에 쓰고 Update는 매 프레임 불립니다. 매뉴얼은 MonoBehaviour에 생성자를 만들면 프로젝트에 큰 문제가 생길 수 있다고 경고합니다.

Unity 6.6은 Roslyn 컴파일러와 C# 9.0을 씁니다. C# 9.0은 2020년 11월에 나온 버전이고 Microsoft Learn은 .NET 11 SDK의 기본 버전으로 C# 15를 안내합니다. C# 9.0 안에서도 init 전용 setter 같은 몇 가지는 유니티가 지원하지 않습니다.

그래서 최신 문법을 쓴 교재의 코드는 유니티에서 컴파일 오류가 날 수 있습니다. 유니티가 목표면 클래스, 제네릭, 람다, 패턴 일치처럼 C# 9.0까지의 문법으로 충분합니다. 레코드는 유니티 직렬화가 지원하지 않아 저장용 형식에는 쓰지 않습니다.

코루틴은 실행을 멈췄다가 다음 프레임에 이어 가는 메서드입니다. 반환 형식을 IEnumerator로 쓰고 yield return에서 멈추며 StartCoroutine으로 시작합니다. 스레드가 아니라 메인 스레드에서 실행되므로 오래 걸리는 계산을 넣으면 안 됩니다.

메모리는 자동으로 관리되지만 매 프레임 실행되는 코드에서는 할당을 줄여야 합니다. 매뉴얼은 임시 문자열과 박싱, 클로저를 피하고 문자열을 많이 이을 때는 StringBuilder를 쓰라고 권합니다. 자주 만들고 없애는 오브젝트는 UnityEngine.Pool로 재사용합니다.

데이터는 ScriptableObject로 코드와 나눌 수 있습니다. 매뉴얼은 프로젝트에 에셋으로 저장해 실행 중에 쓰는 데이터를 주된 용도로 듭니다. 몬스터 능력치나 아이템 표를 여기에 두면 코드를 고치지 않고 값을 바꿀 수 있습니다.

Q5. 기초가 끝났는지 어떻게 확인합니까?

과제 세 개를 순서대로 만들어 보면 됩니다. 콘솔 텍스트 RPG, 유니티 미니게임 한 개, 같은 게임 다시 짜기입니다. 세 번째까지 되면 공고가 요구하는 '직접 쓴 C# 코드'가 생깁니다.

  1. 콘솔 텍스트 RPG — 클래스로 캐릭터와 몬스터를 나누고 List와 Dictionary로 인벤토리를 만듭니다. 1~3단계가 확인됩니다.
  2. 유니티 미니게임 한 개 — Start와 Update로 움직이고 충돌과 점수, 게임 오버 화면까지 넣습니다. 스크립트끼리 값을 주고받아 봅니다.
  3. 같은 게임 다시 짜기 — 상속과 인터페이스로 적 종류를 나누고 이벤트로 UI를 갱신합니다. 오브젝트 풀과 ScriptableObject를 붙이면 4~5단계가 확인됩니다.

[이미지 업로드: 공통_csharp-practice.png / 대체텍스트: C# 기초가 끝났는지 확인하는 과제 3단계 – 과제 1 콘솔 텍스트 RPG(클래스와 List·Dictionary로 인벤토리, 1~3단계 확인), 과제 2 유니티 미니게임 한 개(Start·Update, 충돌, 점수, 게임 오버), 과제 3 같은 게임 다시 짜기(상속·인터페이스, 이벤트, 오브젝트 풀, 4~5단계 확인). 게임잡 유니티 공고 세 건 중 두 건이 직접 쓴 코드를 요구했다]

콘솔 과제는 .NET SDK만 있으면 됩니다. C# 14와 .NET 10부터는 .cs 파일 하나를 dotnet run으로 바로 실행할 수 있습니다(Microsoft Learn). 유니티 없이 문법만 연습하기에 가볍습니다.

두 번째 과제는 Unity Learn 과정의 프로토타입이 참고가 됩니다. 과정은 좌우로 움직이는 자동차, 위에서 내려다보는 게임, 끝없이 달리는 러너, 클릭 게임 등을 차례로 만듭니다. 따라 만든 뒤에는 강의 없이 규칙 하나를 바꿔 다시 만들어 봅니다.

포트폴리오의 차이는 세 번째 과제에서 납니다. Unity Learn 과정도 마지막 미션에서 객체 지향 원칙으로 프로젝트를 다시 짜고 코드를 프로파일링합니다. 처음 버전과 고친 버전을 깃허브에 함께 남기면 무엇을 왜 바꿨는지 설명할 수 있습니다.

첫 게임의 크기를 정하는 방법은 「게임 만들기 처음 시작」 글에 있습니다.

Q6. 유니티 신입 공고는 C#을 어느 수준으로 봅니까?

문법 시험보다 직접 쓴 코드를 봅니다. 2026년 7~9월에 게임잡에 등록된 유니티 공고 세 건을 열어 봤습니다. 세 건 모두 C# 코드나 포트폴리오를 요구했고 두 건은 본인이 쓴 코드를 내라고 적었습니다.

공고 경력 조건 제출물
기어세컨드 클라이언트 무관 C# 코드 첨부
스콘 유니티 개발자 신입 이력서와 포트폴리오(필수)
데브캣 게임 로직 무관 직접 쓴 소스코드 포함

게임잡 공고 원문 기준입니다(2026년 11월 12일 확인). 세 건 모두 채용 시 마감이라 지원 전에 다시 확인하십시오.

기어세컨드는 제출 서류에 '본인의 역량을 표현할 수 있는 C# 코드'를 적었습니다. 기밀이나 저작권 문제가 없고 본인이 작성한 코드여야 한다는 조건도 붙였습니다. 전형은 서류, 사전 질문, 대면 인터뷰 순서입니다.

스콘의 신입 공고는 버추얼 캐릭터 솔루션을 Unity와 C#으로 개발하고 유지보수하는 자리입니다. 쓰는 기술로 Unity 6, URP, C#을 적었고 포트폴리오가 필수입니다. 게임 회사가 아니어도 유니티와 C#을 쓰는 자리가 있다는 예입니다.

데브캣 공고는 경력 무관이지만 C#과 유니티를 쓴 프로젝트의 실무 경험을 지원 자격에 적었습니다. 포트폴리오에는 직접 작성한 소스코드를 넣고 개발 철학과 코딩 스타일이 드러나게 쓰라고 안내합니다. 우대 사항에는 '사람이 이해하기 쉬운 코드에 대한 철학'이 있습니다.

세 공고 모두 결과물을 직접 보여 달라고 요구합니다. Q5의 과제 코드를 깃허브에 올리고 이름 짓기와 클래스 나누기를 다듬어 두는 편이 맞습니다. 면접에서는 그 코드를 왜 그렇게 썼는지 설명할 수 있어야 합니다.

직군 전체의 채용 과정은 「게임회사 취업 준비」 글에 있습니다.

Q7. C#을 어디서 배웁니까?

혼자 시작한다면 Microsoft Learn 자습서와 Unity Learn 과정으로 1~3단계까지 갈 수 있습니다. 내 코드가 읽기 쉬운지는 혼자서 확인하기 어렵습니다. 세 번째 과제부터는 코드를 읽어 줄 사람이 있으면 빠릅니다.

SBS아카데미게임학원 대전점의 게임프로그래밍 과정은 유니티와 언리얼을 모두 다룹니다. 고용24에 국가기간·전략산업직종훈련으로 등록된 국비 과정은 유니티 기준입니다. C# 비중과 진도는 상담에서 과정 구성으로 확인하는 것이 정확합니다.

국비 순서는 상담 → 과정 확인 → 카드 신청입니다. 입과 전에 상담과 간단한 실기로 기초를 확인합니다. 훈련비와 자부담은 고용24에서 과정명으로 확인하십시오.

Update 함수 하나에 코드를 다 넣은 전문대 2학년 (가상 사례)

고민 — "게임은 돌아가는데 코드를 보여 달라는 공고에 낼 자신이 없습니다. C#을 처음부터 다시 해야 하나요?"

확인한 것 — 스크립트 하나의 Update 함수에 입력, 이동, 점수, UI가 모두 들어 있었습니다. 클래스와 List는 쓸 수 있었지만 인터페이스와 이벤트는 써 본 적이 없었습니다. 관심 공고 두 건은 직접 쓴 코드를 요구했습니다.

세운 계획 — 2주 동안 콘솔 텍스트 RPG로 클래스와 컬렉션을 다시 정리하기로 했습니다. 그다음 한 달은 러너 게임을 클래스별로 나누고 이벤트로 UI를 분리하기로 했습니다. 국비는 상담에서 과정 구성을 확인한 뒤 카드 신청 여부를 정하기로 했습니다.

Q. 파이썬이나 자바를 해 봤으면 어디서부터 시작합니까?

Microsoft Learn은 다른 언어 경험자에게 자습서 1~2를 건너뛰고 '튜플 및 형식'부터 시작해도 된다고 안내합니다. 자바, 자바스크립트, 파이썬 개발자를 위한 안내 문서도 따로 있습니다. 이 글의 순서로는 2단계의 값 형식과 참조 형식부터 확인하면 됩니다.

Q. 코루틴과 async/await 중 무엇을 먼저 배웁니까?

유니티에서는 코루틴부터 익히는 편이 쉽습니다. 매뉴얼은 페이드처럼 여러 프레임에 걸친 작업과 에셋 로드 같은 긴 비동기 작업에 코루틴을 쓴다고 설명합니다. 여러 스레드가 필요한 작업에는 잡 시스템이나 Awaitable을 쓴 async/await을 안내합니다.
